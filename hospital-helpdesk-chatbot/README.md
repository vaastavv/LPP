# 🏥 Hospital Helpdesk Chatbot

A multilingual (English / Hindi), voice-enabled hospital helpdesk assistant that
combines a **fine-tuned DistilBERT intent classifier** with a **pretrained
GoEmotions emotion model** to produce empathetic, intent- and emotion-aware
responses, served through a Streamlit UI.

| Component | Technology |
|---|---|
| Intent classification | `distilbert-base-uncased`, fine-tuned (14 intents) |
| Emotion detection | `SamLowe/roberta-base-go_emotions` (pretrained, 28 labels → 5 groups) |
| Response generation | Intent × emotion templates (`data/response_templates.json`, 70 responses) |
| Speech-to-text | OpenAI Whisper |
| Text-to-speech | gTTS |
| Translation | deep-translator (Google), English ⇄ Hindi |
| UI | Streamlit |

---

## 1. Architecture

```
                 🎙️ voice (Whisper STT)        ⌨️ text
                          \                    /
                           v                  v
                      ┌──────────────────────────┐
                      │  Language detection +    │   hi → en  (deep-translator)
                      │  translation to English  │
                      └────────────┬─────────────┘
                                   │ English query
                 ┌─────────────────┴──────────────────┐
                 v                                    v
   ┌───────────────────────────┐        ┌──────────────────────────────┐
   │ Intent Classifier         │        │ Emotion Classifier           │
   │ fine-tuned DistilBERT     │        │ SamLowe/roberta-base-        │
   │ → intent + confidence     │        │ go_emotions (28 labels)      │
   └─────────────┬─────────────┘        │ → positive/neutral/sadness/  │
                 │                      │   fear/anger (configurable)  │
                 │  emergency keyword   └──────────────┬───────────────┘
                 │  safety override                    │
                 └──────────────┬──────────────────────┘
                                v
                  ┌───────────────────────────────┐
                  │ Response Generator            │
                  │ response_templates.json       │
                  │ + hospital_info.json slots    │
                  │ + fallback chain              │
                  └───────────────┬───────────────┘
                                  │  en → hi (if needed)
                                  v
                    💬 Final response  +  🔊 gTTS audio
```

Key design decisions:

* **English-only models, multilingual edge.** Translation happens at the
  boundary so one well-trained English model serves both languages.
* **Safety override.** If the query contains emergency phrases (chest pain,
  unconscious, not breathing, …) the intent is forced to
  `emergency_assistance`, whatever the classifier says. A missed emergency
  costs far more than a false alarm.
* **Confidence-gated responses.** Below a configurable confidence threshold the
  bot asks the user to rephrase instead of guessing.
* **Configuration over code.** Emotion mapping (`config/emotion_mapping.json`),
  hospital details (`config/hospital_info.json`) and responses
  (`data/response_templates.json`) can be changed without touching Python.

## 3. Dataset

`data/intents.csv` is generated by `scripts/generate_dataset.py`, which
combines hand-written patient queries with slot values (specialties,
doctors, days, tests, medicines, insurers, relatives…) and **style
transforms**:

| Style | Example |
|---|---|
| Formal | *Good morning. Whom should I call for my daughter's admission enquiry?* |
| Informal | *yo why is my bill so high yaar* |
| Young / texting | *which urologist is available saturday 😅* |
| Elderly | *Hello, I am a senior citizen and when does Dr. Nair sit in the clinic?* |
| Urgent | *Please cancle all my upcomng appointments urgent!!!* |
| Long | *My family doctor referred me to your hospital. What are the timings of orthopedics? Please let me know the process.* |
| Short | *vitamin supplements without a prescription* |
| Spelling mistakes | *Snake bite emergncy, what to do?* |

**14 intents × 150 examples = 2,100 rows**, 1–33 words per query (mean ≈ 9).

Intents: `appointment_booking`, `appointment_cancellation`,
`appointment_rescheduling`, `doctor_search`, `hospital_timings`,
`emergency_assistance`, `billing_query`, `insurance_query`, `lab_reports`,
`pharmacy_query`, `contact_information`, `greetings`, `thank_you`, `goodbye`.

`scripts/validate_dataset.py` then:

1. checks required columns and **missing values**;
2. drops unknown labels;
3. removes **exact and case/punctuation-insensitive duplicates**, and drops
   texts that appear with **conflicting labels**;
4. reports **class imbalance** (max/min ratio; currently 1.00);
5. performs a **stratified** 70/15/15 split and asserts **no leakage** between
   splits;
6. writes `train.csv`, `val.csv`, `test.csv` and `reports/dataset_report.json`.

> ⚠️ The dataset is synthetic. Before production, augment it with real (anonymised)
> helpdesk logs and re-evaluate on held-out real traffic.

## 5. Training

```bash
make data          # or: python -m scripts.generate_dataset && python -m scripts.validate_dataset
make train         # or: python -m src.train_intent
```

Useful flags for `python -m src.train_intent`:

| Flag | Default | Purpose |
|---|---|---|
| `--epochs` | 10 | maximum epochs (early stopping usually ends sooner) |
| `--lr` | 5e-5 | peak learning rate (AdamW) |
| `--scheduler` | linear | `linear`, `cosine`, `cosine_with_restarts`, `polynomial` |
| `--warmup-ratio` | 0.1 | LR warm-up fraction |
| `--batch-size` | 16 | per-device train batch |
| `--max-length` | 64 | max tokens per query |
| `--patience` | 3 | early-stopping patience (epochs) |
| `--metric` | f1_macro | validation metric used to select the best checkpoint |
| `--fp16` | off | mixed precision on CUDA |

What the pipeline does:

* tokenisation with truncation and **attention masks**; **dynamic padding**
  per batch (`DataCollatorWithPadding`);
* AdamW with weight decay and a **warm-up + decay LR schedule**;
* evaluation and **checkpointing every epoch**, keeping the best 2;
* **early stopping** on validation macro-F1, then the **best checkpoint is
  reloaded** and saved to `models/intent_classifier/` (with tokenizer,
  `label_map.json`, `training_args.json`, `metrics.json`).

Expect a few minutes on a GPU, or roughly 10–20 minutes on a modern CPU.

## 6. Evaluation

Training finishes by evaluating on the test split. Outputs in `reports/`:

* `intent_metrics.json` – accuracy, precision, recall and F1 (macro + weighted)
  for train/val/test, per-class F1, and the full training log history;
* `test_classification_report.txt/.json`;
* `test_confusion_matrix.csv/.png`;
* `test_errors.csv` – every misclassified test query, for error analysis.

Re-evaluate any time, or on new labelled data (e.g. real user queries):

```bash
python -m src.evaluate_intent                                   # test split
python -m src.evaluate_intent --data data/val.csv --prefix val
python -m src.evaluate_intent --data real_queries.csv --prefix real
```

Metrics come from Hugging Face `evaluate`. If its metric scripts can't be
fetched (offline), scikit-learn computes the same numbers instead.

Try the components directly:

```bash
python -m src.intent_predictor "I want to see a cardiologist tomorrow"
python -m src.emotion_detector "My father is having chest pain, please help!"
python -m src.chatbot            # interactive CLI chat
```

Run the tests (they use stubbed models, so no downloads or network are needed):

```bash
make test
```

## 7. Emotion detection

`SamLowe/roberta-base-go_emotions` is used **as is**, with no training. It
returns independent sigmoid scores for all 28 GoEmotions labels, which are
collapsed into five groups via `config/emotion_mapping.json`:

| Group | GoEmotions labels |
|---|---|
| positive | admiration, amusement, approval, caring, desire, excitement, gratitude, joy, love, optimism, pride, relief |
| neutral | neutral, curiosity, realization, surprise, confusion |
| sadness | sadness, grief, disappointment, remorse, embarrassment |
| fear | fear, nervousness |
| anger | anger, annoyance, disapproval, disgust |

Settings in the same file:

* `aggregation`: `max` (default) or `sum` of member-label scores per group;
* `neutral_override_threshold`: if `neutral` wins but a non-neutral group
  scores at least this much, the non-neutral group is used (GoEmotions
  over-predicts neutral on short service requests);
* `min_confidence` / `default_group`: what to fall back to when every score is weak.

## 8. Response generation and fallbacks

`ResponseGenerator.generate(intent, emotion, confidence)` picks
`templates[intent][emotion]` and fills `{placeholders}` from
`config/hospital_info.json`. Fallbacks, in order:

1. missing intent or confidence below threshold → emotion-aware **clarification** prompt;
2. intent not in the templates → **generic fallback** with the helpline;
3. emotion variant missing → the intent's **neutral** variant (or its first available one).

## 9. Voice and translation

* `src/audio.py`
  * `speech_to_text(audio, language=None, model_size="base")` takes a path or raw
    bytes and returns `Transcription(text, language)`;
  * `text_to_speech(text, lang="en")` returns MP3 bytes.
* `src/translator.py`
  * `to_english(text, source_lang=None)` detects Hindi by Devanagari script
    (Whisper's language or the UI selection can override it) and translates
    the query to English;
  * `from_english(text, target_lang)` translates the response back.
  * Translation errors never break the chat: the original text is returned
    and a warning is logged.

## 10. Running the app

```bash
make app            # or: streamlit run app.py
```

Features: text **and** voice input (`st.audio_input` + Whisper), automatic or
manual language selection, intent badge with confidence, emotion badge,
top-3 intents and emotion-group scores, persistent chat history, spoken
replies (gTTS) and an emergency banner.

## 11. Deployment

**Docker**

```bash
make train                                  # produce models/intent_classifier/
docker build -t hospital-helpdesk-chatbot .
docker run -p 8501:8501 -v $(pwd)/models:/app/models hospital-helpdesk-chatbot
```

The image installs `ffmpeg`, uses CPU-only PyTorch, and exposes Streamlit's
health endpoint as a Docker `HEALTHCHECK`.

**Other targets**

* *Streamlit Community Cloud / Hugging Face Spaces*: push the repo, add
  `ffmpeg` to `packages.txt`, and upload the trained model to the HF Hub
  (`trainer.push_to_hub`), pointing `IntentPredictor` at that repo id.
* *Production API*: `HelpdeskChatbot.respond()` has no UI dependencies, so it
  can be wrapped in FastAPI behind a load balancer, with models loaded once
  per worker.

**Operational notes**

* Models are cached with `st.cache_resource`, so each process loads them only once.
* Set `WHISPER_MODEL=tiny|base|small` to trade accuracy for latency.
* gTTS and Google Translate need outbound internet access. For air-gapped
  hospitals, swap them for offline engines (e.g. IndicTrans2, Coqui/Piper TTS).
* Never log raw patient messages in production without consent; scrub PHI first.

## 12. Future improvements

* Fine-tune on **real, anonymised helpdesk transcripts**; use active learning
  on low-confidence queries.
* **Slot filling / NER** (doctor, date, test) and integration with the
  hospital's HIS/appointment API to actually book, cancel and reschedule.
* **Multi-turn dialogue state**, e.g. "book with Dr. Sharma" → "which day?".
* Native **Hinglish / code-mixed** support (e.g. MuRIL or IndicBERT) instead of
  translate-then-classify; more Indian languages.
* An **out-of-scope** intent and calibrated confidence (temperature scaling).
* RAG over hospital FAQs and policies for open-ended questions, with an LLM
  constrained to retrieved facts.
* **MLOps**: experiment tracking (MLflow/W&B), data and model versioning (DVC /
  HF Hub), CI running tests plus an accuracy gate, drift monitoring on
  live intent/emotion distributions, and human hand-off analytics.
* Model compression (ONNX / quantisation) for faster CPU inference.
* Accessibility: larger-font mode, slower TTS for elderly users.
